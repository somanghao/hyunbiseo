## 1. 목적 · 심사 4축

식사 시간에 도착하는 길이면 **도착 1km 전에 한마디**("도착하면 점심이에요 — 국밥집 세 곳 찾아 뒀어요") 하고, **차를 세우면 목적지 근처 식당 카드**를 보여 준다. 고르면 그곳으로 안내한다.

- 차량특화성: 목적지·도착 예정 시각·남은 거리(내비)로 '언제 말할지'를 정한다 — 폰 지도 앱은 도착 시각을 모른 채 검색만 한다
- 창의성: 묻기 전에 먼저 — 취향(국밥) + 도착 시각(12:10) + 목적지 좌표를 한 번에 합친다
- 기술활용성: NaviHelper 목적지·남은 거리·`requestRoute`(실측) · 카카오 로컬 키워드 검색(실측 11-08) · 서버 취향 `taste.json`
- 사업성: 식당·주차 제휴(예약·쿠폰) · 쇼핑몰 행사 — 도착지 기반 커머스

## 2. 11-15 MVP 시연 장면

1. 정차 · 11시 50분(시연 `--es clock 11:50`) · 취향에 '음식: 국밥'("나 국밥 좋아해") · "현비서야 강남역 가자"
2. 주행(D · 60km/h) → 남은 1km(앱 `near` 이벤트) → 도착 예정 = 점심 → 서버가 카카오에서 **강남역 반경 500m '국밥'** 검색 → "도착하면 열두 시 십 분 점심이에요. 140미터 옆 콩뿌리 콩나물국밥으로 **바로 갈까요?** 다른 곳은 내리면 보여 드릴게요"(듣기) + 내비 판 아래 한 줄
3. **"응"** → 그 식당으로 `requestRoute`(주행 중 고르기 = 차로 안내 — E2E e18) / **"아니 내려서 볼게"** → 도착·정차(P · 앱 `arrived`) → **도착 추천 카드 5곳**(이름 · 목적지에서 m · 종류 · 걸어서 N분 — E2E e17)
4. 정차 중 "두 번째 거기 어디야" → 500m 안이면 "걸어서 3분, 북서쪽이에요"(경로는 안 바꿈) · 500m 넘거나 "차로 가자"면 그곳으로 경로
5. (안 하는 경우) 목적지가 식당·카페면 · 식사 시간이 아니면 · 조용히 모드면 · 오늘 같은 목적지에서 이미 했으면 먼저 말하지 않음

## 3. 언제 켜지나

| 트리거 | 조건 |
|---|---|
| 곧 도착 제안 | 앱 `near`(남은 1km · 총 2.5km 넘는 길) + 도착 예정이 **식사 시간**(점심 11:00~13:30 · 저녁 17:30~20:00 — 질문 1) + 목적지가 식당·카페 아님 + 그 길에서 한 번 |
| 도착 카드 | 앱 `arrived`(남은 150m 안 · 정차) — 곧 도착 때 찾은 결과(그 주행 메모리)로, 없으면 그때 검색 |
| 말로 묻기 | "근처 맛집" · "점심 어디서 먹지" · "카페는?" — 식사 시간이 아니어도(대답) |
| 고르기 | "첫 번째로 안내해 줘" · "다른 데" · "더 가까운 데" |
| 안 함 | 조용히 모드 · 목적지 분류가 음식점(FD6)·카페(CE7) · 오늘 같은 목적지에서 이미 함 |

## 6. 앱 기능 — `feature/ArriveFeature.kt`

- `ctx`: 목적지 좌표 `destLat`·`destLng`(지금은 이름·남은 거리·`eta`만) · 시연 시계(`clock`)
- 이벤트: 기존 `near`·`arrived` 그대로(새 이벤트 없음) — 서버가 추천을 붙인다
- `onReply`: 카드 = 기존 목록 카드(`card`) · 고르기 = 두뇌 답 `nav{name,lat,lng}` → `RouteFeature.goTo` 그대로 · 한 줄 `arrive_line`
- `render`: 주행 중 한 줄(1칸 = 내비 판 바로 아래 · 반반 = 길 카드 끝) — 그리기 훅 자리
- `fallback`(두뇌 없음): "근처 먹을 곳 띄웠어요"(카드는 서버가 만들었을 때만)

## 7. 서버 기능 모듈 — `server/hyun/features/places.py`

- `kakao(query, lat, lng, radius=500, cat="FD6")` 어댑터 — 키 `data/places.json` · **실시간 호출만**(결과를 파일에 쓰지 않음 · 그 주행 동안 메모리에만)
- `on_in`: `near`·`arrived` + 식사 시간 + 목적지가 식당 아님 → 검색어 = 취향 음식 상위 1~2(없으면 FD6 전체) → msg에 결과
- `block`: `[주변 장소]` — 번호 · 이름 · 목적지에서 m · 종류 · 좌표(두뇌가 고를 때 nav에 쓰게)
- `post`: **카드는 서버가 만든다**(교통 표와 같은 방식 — 두뇌가 이름·거리를 옮기다 틀리지 않게) · 제목 "강남역 근처 점심 · 국밥 취향" · 출처 "카카오 로컬 · 실시간"
- `RULES`: 식사 시간·식당 목적지 판단은 서버가 했으니 두뇌는 말만 · 장소 이름은 `[주변 장소]`에 있는 것만(지어내지 않음) · 고르면 nav에 그 좌표 · 걷는 거리면 "걸어서 N분"
- 로그: `log.jsonl`·최근 대화에 장소 이름을 남길지 = 열린 질문 6(기본안: 개수만 `places|kakao|n=5`)

## 8. 주행 규칙

- 주행 중: 말 한 문장 + 한 줄(글자만 — 이름 목록 없음) · 카드 숨김
- 정차: 카드 5곳(누르면 닫힘) · 고르기는 말로(터치도 됨)

## 9. E2E 케이스 — `tools/hyun_e2e/cases.json` e17 · e18 (정본은 그 파일)

- **e17** 점심 시간 곧 도착 · 국밥 취향 · 내려서 카드: "나 국밥 좋아해" → `--es clock 11:50` → 강남역 경로 → D·60km/h → `--es event near` → 한마디 + 한 줄(`arrive|line|`) → "아니 내려서 볼게" → P → `--es event arrived` → 카드(`card|…근처…|5|`) · 서버 기록 `"places": "kakao|near`(이름 없이 검색어·개수)
- **e18** 곧 도착 제안에 "응" → 그 식당으로 경로(`nav|` 강남역 아닌 곳 → `routeStarted`) — 현비서 화면 지키기도 같이 확인
- 케이스 설명 슬라이드: e17 **상황** "11시 50분 · 국밥 좋아함 · 강남역 가는 중(도착 예정 점심)" · **내가 할 말** "나 국밥 좋아해" → (곧 도착 제안에) "아니, 내려서 볼게" / e18 **내가 할 말** "응, 거기로 가자"
