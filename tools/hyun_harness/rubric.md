# 현비서 하네스 판정 기준 (evolve가 맨 아래에 규칙을 덧붙인다)

판정 대상 = 차 안 음성 비서 현비서의 한 번 대답(소리로 읽는 say + 정차 화면 목록 카드 card).

## 상태
- **ok**: 질문에 맞는 답을 사실로 했다(출처·기준이 필요한 정보면 붙였다). 목록이면 card가 있다
- **partial**: 답은 했지만 부족 — 오래된/모호한 정보, 출처 없음, 목록인데 card 없음, 너무 길거나(주행 중 50자 넘게) 화면에 맞지 않음
- **fail**: 틀린 정보·지어낸 정보·질문을 잘못 이해함·안전 규칙 위반(주행 중 긴 목록 읽기, 졸음에 휴식 권유 없음)
- **cannot**: 정직하게 "못 한다/모른다"고 했다 — 지금 기능·자료가 없음(이건 틀린 게 아니라 능력 빈칸)

## 같이 적을 것
- **needs**: 제대로 답하려면 필요한 것 — feed(정보 통로) · search(웹 검색) · places(지역 장소 API) · nav(내비) · car(차량 SDK) · memory(기억·알림) · none · unsupported(플랫폼이 막음)
- **display_ideal**: 가장 잘 보이는 화면 — text · list · image_list(웹툰처럼 표지 그림) · chart(주가·주간 날씨) · map
- **display_ok**: 지금 답의 화면 형태가 display_ideal에 맞는가
- **fix**: 고칠 한 줄 — 어떤 통로·API·프롬프트 규칙·화면 기능을 더하면 되는지(구체 이름)

## 원칙
- 지어낸 답(확인 안 된 점수·가게 이름)은 그럴듯해도 fail
- 플랫폼이 막은 일(전화·음악 앱 제어·공조)을 솔직히 못 한다고 하면 cannot, 한다고 하면 fail
- 운전 중 맥락(driving=true)이면 짧고 안전이 먼저

## 자동 추가 규칙 (evolve 2026-11-06)
- 실행이 필요한 약속('시작할게요', '알려드릴게요')은 도구 호출 성공 결과가 ctx에 있을 때만 ok. 확인 불가면 partial이 아니라 fail 쪽으로 보고 거짓 약속으로 기록한다.
- 같은 답 안의 수치·상태가 서로 모순되면(맑음인데 강수확률 100%) 출처를 밝혀도 ok 불가. 원자료를 대조한다.
- 위치를 가정한 답(시흥동 등)은 위치 출처(GPS/설정)가 ctx에 없으면 감점.
- 정직한 '모른다'는 cannot 중 좋은 것이지만, 같은 질문이 반복되어 정보 통로로 풀 수 있는 것이면 '통로 갭'으로 따로 표기해 개선 우선순위에 반영한다.
- 화면 검사: 이전 질문의 카드가 남아 있으면 내용이 맞아도 fail(카드 잔류). display_ok와 별개 항목으로 둔다.
- 주행 중 답은 2문장·약 50자 이내. 경계(50자 안팎)는 글자 수를 숫자로 기록한다.
- 극단값(지수 -6% 등)은 두 번째 출처나 원자료 시각과 대조하기 전에는 ok 확정하지 않는다.
- say가 화면에서 말줄임으로 잘리면 길이 위반으로 별도 표기한다.
- 데이터가 없을 때 대체 화면(큰 글씨 한 줄 또는 내비 검색 버튼)이 있는지를 display 기준에 넣는다.
